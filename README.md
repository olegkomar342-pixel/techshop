# TechShop — интернет-дүкен (электроника және аксессуарлар)

**Орындаған:** Бексұлтан, Алибек, Исатай

Тауарларды онлайн сатуға арналған full-stack веб-қосымша: санаттары бар каталог, іздеу және сүзгілер,
себет, тапсырысты рәсімдеу, жеке кабинет, пікірлер мен бағалар, әкімші панелі.

```
HTML + CSS + JavaScript   (frontend/)
          ↓  fetch()
      HTTP / REST API  (JSON)
          ↓
     Backend — Go       (backend/)
          ↓  pgx
       PostgreSQL       (database/01_schema.sql)
```

## Технологиялық стек

| Қабат    | Технологиялар |
|----------|---------------|
| Frontend | HTML + CSS + таза JavaScript (фреймворксыз), `fetch()` |
| API      | REST, HTTP, JSON; қателердің бірыңғай форматы `{ "error": "..." }` |
| Backend  | **Go 1.22+**: стандартты `net/http` (маршруттау), `pgx/v5` (PostgreSQL), `bcrypt`, JWT, баптаулар `.env` арқылы |
| Дерекқор | PostgreSQL, pgAdmin арқылы әкімшілендіру |

> Жоспарда бэкенд Node.js (Express) деп көрсетілген. Бэкенд **Go** тілінде жазылды: API, дерекқор
> және фронтенд жоспардағыдай, тек бэкенд тілі өзгерді.

## Іске қосу (Windows / macOS / Linux)

**Керек:** [Go 1.22+](https://go.dev/dl/), PostgreSQL + pgAdmin.

1. **Дерекқор.** pgAdmin-де `shop` дерекқорын құрыңыз → оны таңдап, **Query Tool** ашыңыз →
   `database/01_schema.sql` файлын ашып, орындаңыз (F5).
   > Файл басында кестелер жойылады (`DROP TABLE`), сондықтан оны қайта орындасаңыз, деректер бастапқы күйге қайтады.
2. **Баптаулар.** `backend` қалтасында `.env.example` файлын `.env` деп көшіріп, `DB_PASSWORD`
   (PostgreSQL құпиясөзі) және `JWT_SECRET` (кез келген ұзын жол) мәндерін жазыңыз.
3. **Сервер.** Терминалда:
   ```bash
   cd backend
   go run .
   ```
   Бірінші іске қосқанда Go тәуелділіктерді өзі жүктейді.
4. Браузерде ашыңыз:
   - сайт: <http://localhost:3000>
   - API: <http://localhost:3000/api/products>

## Интернетте орналастыру (24/7)

Тегін нұсқа: **Neon** (PostgreSQL дерекқоры) + **Render** (Go сервері, `render.yaml` бойынша).

1. **GitHub:** жаңа репозиторий ашып, `shop` қалтасының ішіндегісін жүктеңіз (`backend/.env` файлын **жүктемеңіз**).
2. **Neon** (neon.com): жаңа жоба, аймақ — Frankfurt → **Connect** → connection string көшіріңіз.
3. **Render** (render.com): **New → Blueprint** → репозиторийді таңдаңыз → `DATABASE_URL` (Neon сілтемесі)
   және `ADMIN_PASSWORD` (әкімшінің жаңа құпиясөзі) енгізіңіз → **Deploy**.
4. Бірінші іске қосуда сервер бос дерекқорға `01_schema.sql` файлын өзі жүктейді.

Баптаулар (орта айнымалылары):

| Айнымалы | Мақсаты |
|----------|---------|
| `DATABASE_URL` | Дерекқор сілтемесі (Neon/Render/Railway береді) |
| `JWT_SECRET` | Токендерге қол қою кілті (Render өзі жасайды) |
| `ADMIN_PASSWORD` | `admin@shop.kz` құпиясөзі — интернетте **міндетті** |
| `PORT` | Платформа өзі қояды |

Тегін Render сервисі 15 минут бос тұрса «ұйықтайды» (келесі ашылу ~1 минут). Ұйықтатпау үшін UptimeRobot-та
сайттың басты бетін (`/`, `/api/health` емес) 5 минут сайын тексеретін монитор қосыңыз.

## REST API

Кіруді талап ететін сұраныстарға `Authorization: Bearer <token>` тақырыбы жіберіледі
(токенді `/api/auth/login` немесе `/api/auth/register` қайтарады).

| Әдіс | URL | Сипаттамасы | Рұқсат |
|------|-----|-------------|--------|
| GET | `/api/products` | Каталог. Параметрлер: `q` (іздеу), `category`, `min_price`, `max_price`, `in_stock=1`, `sort` (`newest`, `price_asc`, `price_desc`, `rating`, `name`), `page`, `limit` | бәрі |
| GET | `/api/products/:id` | Тауар беті, пікірлерімен және орташа рейтингімен | бәрі |
| GET | `/api/categories` | Санаттар (ішкі санаттармен) | бәрі |
| POST | `/api/auth/register` | Тіркелу `{ email, password, full_name, phone }` | бәрі |
| POST | `/api/auth/login` | Кіру `{ email, password }` → `{ token, user }` | бәрі |
| GET, PUT | `/api/me` | Профильді көру / өңдеу (құпиясөзді ауыстыру) | пайдаланушы |
| GET | `/api/cart` | Себетті көру | пайдаланушы |
| POST | `/api/cart` | Тауар қосу `{ product_id, quantity }` | пайдаланушы |
| PUT | `/api/cart/:productId` | Санын өзгерту `{ quantity }` | пайдаланушы |
| DELETE | `/api/cart/:productId`, `/api/cart` | Тауарды жою / себетті тазалау | пайдаланушы |
| POST | `/api/orders` | Тапсырысты рәсімдеу `{ full_name, phone, shipping_address, delivery_method, payment_method, comment }` | пайдаланушы |
| GET | `/api/orders`, `/api/orders/:id` | Тапсырыстар тарихы | пайдаланушы |
| POST | `/api/orders/:id/cancel` | «Жаңа» тапсырысты болдырмау | пайдаланушы |
| POST | `/api/products/:id/reviews` | Пікір қалдыру/өзгерту `{ rating: 1–5, comment }` | пайдаланушы |
| DELETE | `/api/reviews/:id` | Пікірді жою (автор немесе әкімші) | пайдаланушы |
| GET | `/api/admin/stats` | Статистика | әкімші |
| GET, POST | `/api/admin/products` | Барлық тауарлар / жаңа тауар | әкімші |
| PUT | `/api/admin/products/:id` | Өңдеу, жасыру (`is_active: false`) | әкімші |
| POST, DELETE | `/api/admin/categories[/:id]` | Санат қосу / жою | әкімші |
| GET | `/api/admin/orders?status=` | Барлық тапсырыстар | әкімші |
| PUT | `/api/admin/orders/:id/status` | Күйді өзгерту `{ status }` | әкімші |

**Қате кодтары:** `400` — деректер қате, `401` — кіру керек, `403` — рұқсат жоқ, `404` — табылмады,
`409` — email бос емес, `500` — сервер қатесі. Валидация қатесінде өрістер бойынша `fields` объектісі де қайтарылады.

### Тапсырысты рәсімдеу (бір транзакцияда)

1. Себеттегі тауарлардың жолдары `SELECT ... FOR UPDATE` арқылы бұғатталады.
2. Әр тауардың қалдығы тексеріледі, жетпесе `400` қайтарылып, ештеңе өзгермейді.
3. Тапсырыс және оның позициялары жасалады (атауы мен бағасы сатып алу сәтіндегідей сақталады).
4. Қойма қалдығы азаяды, жеткізу құны мен жалпы сома `NUMERIC` арқылы есептеледі.
5. Себет тазаланады → `COMMIT`. Кез келген қате болса — `ROLLBACK`.

Екі сатып алушы соңғы тауарды бір мезгілде алғысы келсе, `FOR UPDATE` арқасында тек біреуі сатып алады
(`TestConcurrentLastItem` тесті 5 параллель сатып алушымен тексереді).

**Жеткізу:** курьер — 1 500 ₸ (50 000 ₸-ден бастап тегін), өзі алып кету — тегін.
**Төлем:** қолма-қол немесе карта (алған кезде). Онлайн төлем жоспарға кірмейді, сондықтан «Төленді» күйін әкімші қолмен қояды.
Тапсырыс болдырылмаса, тауарлар қоймаға қайтарылады.

## Қауіпсіздік

- Құпиясөздер тек **bcrypt** хэші түрінде сақталады; кіру кезінде email бар-жоғы ашылмайды.
- Барлық SQL сұраныстары **параметрленген** (`$1, $2 ...`) — SQL-инъекциядан қорғау; сұрыптау тек рұқсат етілген тізімнен.
- JWT токені HS256 алгоритмімен қол қойылады; пайдаланушының рөлі әр сұраныста дерекқордан тексеріледі.
- Фронтендте барлық пайдаланушы мәтіні `esc()` арқылы экрандалады (XSS-тен қорғау).
- Сұраныс денесі 1 МБ-пен шектелген, сервердің ішкі қателері клиентке көрсетілмейді.

> Сынақ аккаунттарының құпиясөздері белгілі. Сайтты интернетке шығармас бұрын оларды ауыстырыңыз немесе жойыңыз
> және `JWT_SECRET` мәнін ұзын кездейсоқ жолға өзгертіңіз.

## Тестілеу

```bash
cd backend
go test ./...
```

Бұл команда дерекқорсыз бірлік тесттерін іске қосады. API-дың толық тесттері үшін **бөлек** сынақ дерекқорын
(мысалы, `shop_test`) құрып, оның мекенжайын беріңіз. Ол дерекқор әр тест алдында **тазаланады**:

```bash
TEST_DATABASE_URL="postgres://postgres:ПАРОЛЬ@localhost:5432/shop_test?sslmode=disable" go test -p 1 -v ./...
```

Windows PowerShell:

```powershell
$env:TEST_DATABASE_URL="postgres://postgres:ПАРОЛЬ@localhost:5432/shop_test?sslmode=disable"; go test -p 1 -v ./...
```

Тесттер тексеретіні: тіркелу/кіру, 401/403, каталог сүзгілері мен іздеу, тапсырыс транзакциясы, қалдық жетпегенде
ROLLBACK, соңғы тауарға параллель тапсырыс, болдырмау кезінде қалдықтың қайтарылуы, әкімші функциялары, пікірлер.
